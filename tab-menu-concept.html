四個決定，不是換皮the why

這不是網頁選單：它是一個由 mod 自繪的 gpui popup，沒有 CSS、沒有內建子選單，Enter 直接執行命令。右鍵也能作用在背景分頁，所以「這是哪個分頁」比裝飾更重要。

  • 01
    先說它是誰選單頂部顯示分頁名稱、工作區與顏色／pin 狀態。208px 的選單沒有任何上下文，按到哪個分頁只能靠記憶。
  • 02
    用空間分組，不改命令順序列高 30px、圓角 8px、細線與留白把 Layout / Tab / Close 分開。A 保留 Orca 的每一列與順序，所以現有的 parity 註解仍然成立。
  • 03
    危險動作晚一點變紅Close 平常與一般列同色，hover 或鍵盤選取才轉紅。少一點警示色，選單就不會一直像錯誤對話框。
  • 04
    快捷鍵長得像按鍵⌘W、f2、⌘D、⇧⌘D 直接對應 keys.json，用 chip 呈現，掃視時不會跟標籤混在一起。

落在 Herdr 上，哪些做得到？feasibility

設計判定怎麼做 / 限制
列高、字級、icon、快捷鍵 chip可全部在 orca-menu 的 render 內；現有 shortcut() 已能讀 keys，再加一個 cmd- → ⌘ 的 formatter。
208 → 272px可改 orca-tabs 右鍵那一個 openOverlay width；其他選單不動。
分頁／工作區 context header可target.id 已在 spaces() 找得到分頁與 workspace 名稱。
顏色盤移到 header（B）中技術上可，但會偏離 Orca 的順序；A 把顏色留在原位，只在 header 顯示目前色。
外框 14px 圓角＋柔和陰影可，需測frame:"none" 讓 mod 自繪；shadow_lg 存在，但要確認 popup 尺寸與截圖一致。
鍵盤游標、hover、Enter可現有 this.at 與 on_key_down 已具備，只是換視覺。
Firefox 式子選單（B）中第二個 popup；orca-new-menu 的 flyout 可參考，但要多寫 hover intent、Esc 與外部點擊狀態。
毛玻璃 / 背景模糊不可window_blur 只作用在 layout root；popup 沒有 backdrop blur。B 的玻璃僅為示意。
進場動畫不可popup 由 host 顯示，mod 拿不到那一格。HTML 的淡入只是預覽效果。
建議路線

先走 A，B 當成有意識的分歧。

A 拿走 Firefox 真正有用的部分：大一點的目標、清楚的分隔、上下文，以及安靜的危險色；它不改命令、不改順序，也不碰 host 畫不到的東西。視覺回報最高、parity 風險最低。

B 的價值在「子選單減少了列數」，不在玻璃。若一週後仍覺得選單太長，再以 A 為底加一層 flyout；不要一次把顏色、順序、子選單與玻璃全部換掉。

成本與風險

Aorca-menu/main.js（列高、寬度、header、hover、footer）＋ orca-tabs 一個 width。半天內可看到，check + shot 就能驗收。
B多一個 submenu popup、hover intent、Esc／外部點擊狀態；1–2 天，而且玻璃仍然做不到。
注意選單會從約 400px 長到約 500px。13 吋螢幕還放得下；B 的 36px 列高＋header 逼近 600px，先不做。
這不是 Herdr 的實際截圖：字型、圓角、陰影與 popup 位置在 app 內會略有差異。驗收以 herdr-app shot 為準。 內容對應 mods/orca-menu/main.js 的 tab case。
