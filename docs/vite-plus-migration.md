## Coverage evidence

The baseline was lowered from `95.99%` on 129 loaded files to `93.58%` on 152 loaded
files before this audit. That is not treated as a silent pass. Replaying the tree that
published the 95.99 baseline (`6a600c0`; its baseline file records `3f0c4b2`) gives:

| Scope                       | Loaded files |           Line coverage |
| --------------------------- | -----------: | ----------------------: |
| Baseline replay (`6a600c0`) |          125 |                  96.29% |
| Current branch              |          152 |              92.8–92.9% |
| Paths present in both       |           51 | 94.24% → 93.35% (−0.89) |

74 old paths were removed or renamed and 101 new paths are measured. On the comparable
paths the drop is 0.89 points, inside the one-point gate; the larger overall change is
a measurement-scope change, not a 3-point test regression. Raising or keeping the old
95.99 gate against the new scope would require either new tests for the added files or
owner approval to keep the refreshed baseline. Neither has been granted, so this stays
a blocker rather than an unexplained PASS.

## Blockers (not done)

1. **Full TypeScript migration.** 94 handwritten production JavaScript files remain
   (about 21,375 lines), plus 136 test files. With the real generated host declarations
   (`herdr-app 0.1.18`, `gpui-shell 0.7.1`), a `tsrs` pass over the tree reports 1,676
   diagnostics; `orca-ui/shared` alone reports 614 with implicit-any checking. Fixing
   that is a source rewrite, not a rename. Adding `any`/`@ts-ignore`/`@ts-nocheck` to
   force a green count would violate the review's own rule, so it was not done.
2. **One source of truth for the viewport pilot.** `tools/vite-plus-pilot/src/list-viewport.ts`
   and `orca-ui/shared/list-viewport.js` still both exist. The delivery compiler
   replaces the three generated copies, but the handwritten source remains duplicated.
3. **Source-only repository and delivery.** `mods/` is still tracked and the 45 shared
   copies are still generated by `scripts/build-orca-ui.mjs`. The delivery payload is
   byte-preserving legacy JavaScript with one compiled TypeScript module, not a
   fresh-clone, source-only build.
4. **Custom build/lint infrastructure.** `scripts/build-orca-ui.mjs`, `compare-lint.mjs`
   and `compare-lint.mjs` remain necessary while the legacy path is the production
   source. They can only be deleted after blockers 1–3 close. (`compare-runtime.py` was
   deleted with the candidate workflow.)

## Gates that must stay true

- No force push, no merge by the agent, no extra migration PR, no live config deploy.
- No new `any`/`@ts-ignore`/`@ts-nocheck` to hide type errors.
- No automatic golden rewrite; `GOLDEN_RECORD=1` is explicit.
- Full tests, native load and delivery verification must pass before merge.
